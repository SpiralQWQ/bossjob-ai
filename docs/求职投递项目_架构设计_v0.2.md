## 1. 项目概述

### 1.1 目标
为求职者提供 BOSS直聘 一站式 AI 求职助手（**Electron 桌面应用**）：简历解析/优化 → JD 匹配 → 打招呼语生成 → **人类确认后**自动投递 → 模拟面试 → 求职看板。全流程本地化、隐私优先。

### 1.2 核心原则
| 原则 | 说明 |
|------|------|
| 🔒 隐私本地化 | 简历/投递数据全存本地 SQLite，不上传服务器 |
| 🛡️ 人类把关 | AI 全自动评估，**每次投递需人工确认**（career-ops 模式） |
| ⚖️ 合规限速 | 每日投递 ≤15、随机间隔、触发风控立即停（lakejobai 模式） |
| 🧩 模块化 | 决策层（AI）与执行层（浏览器）解耦，便于扩展/降级 |
| 🇨🇳 中文优先 | LLM 用 DeepSeek/Qwen，匹配引擎支持中文向量 |

### 1.3 用户画像
非技术背景求职者（产品经理/运营向），希望"AI 帮我把简历和投递变得聪明、省心"，同时不希望被平台封号。

## 2. 总体架构

```
┌────────────────────────────────────────────────────┐
│  Electron 桌面应用                                  │
│  ┌──────────────────────────────────────────────┐  │
│  │ 渲染进程（React + TS）— UI                    │  │
│  │  简历编辑器 / JD匹配 / 投递控制台 / 模拟面试 / 看板 │  │
│  └──────────────────┬───────────────────────────┘  │
│  ┌──────────────────▼───────────────────────────┐  │
│  │ 主进程（Electron main）— 窗口/生命周期/桥接      │  │
│  │  Spawn & 管理 Python 后端进程                   │  │
│  └──────────────────┬───────────────────────────┘  │
└─────────────────────┼─────────────────────────────┘
                      │ HTTP 127.0.0.1:PORT (local)
┌─────────────────────▼─────────────────────────────┐
│  Python 后端（FastAPI）— 决策层                    │
│  ┌──────────────────────────────────────────────┐  │
│  │ · 简历解析器（PDF/DOCX → 结构化）              │  │
│  │ · JD 匹配引擎（FastEmbed 向量 + 关键词）        │  │
│  │ · 简历优化器（LLM：STAR/ATS/毒舌点评）          │  │
│  │ · 打招呼语生成器（LLM，多风格）                 │  │
│  │ · 模拟面试引擎（LLM + RAG 知识库）             │  │
│  │ · 投递控制器（限速/去重/状态机）                │  │
│  │ · SQLite 数据层（SQLAlchemy）                 │  │
│  └──────────────────┬───────────────────────────┘  │
└─────────────────────┼─────────────────────────────┘
                      │ 控制（DrissionPage 驱动）
┌─────────────────────▼─────────────────────────────┐
│  浏览器执行层（真实 Chrome + DrissionPage）          │
│  BOSS直聘：登录 / 抓岗位 / 投递 / 读取聊天           │
│  验证码/滑块 → 暂停等待人工                          │
└────────────────────────────────────────────────────┘
        AI 服务：DeepSeek + Qwen（用户已有 API）
```

### 2.1 进程模型
| 进程 | 技术 | 职责 |
|------|------|------|
| Electron 主进程 | Node.js | 窗口管理、生命周期、**spawn 并守护 Python 后端**、崩溃重启 |
| Electron 渲染进程 | React | 全部 UI、与主进程 IPC、与后端 HTTP |
| Python 后端 | FastAPI + Uvicorn | AI 决策、数据、自动化控制，本地 127.0.0.1 监听 |
| 浏览器 | Chrome (DrissionPage) | 实际访问 BOSS，独立 user-data-dir |

> **关键**：Electron 启动时自动拉起 Python 后端；关闭时优雅退出。后端作为子进程受主进程守护（seek-stars 进程管理差 → 我们修复）。

## 4. 前端设计（Electron 渲染进程）

### 4.1 页面结构（路由）
| 路由 | 页面 | 说明 |
|------|------|------|
| `/` | 工作台 Dashboard | 今日匹配/待确认投递/看板概览 |
| `/resume` | 简历编辑器 | 解析导入、结构化编辑、AI 优化、多模板预览导出 |
| `/jobs` | 岗位库 | 抓取/手动录入岗位、筛选、批量匹配 |
| `/match/:jobId` | 匹配详情 | 匹配分、关键词高亮、优化建议 |
| `/apply` | 投递控制台 | 打招呼语预览 → 勾选确认 → 投递 → 结果回写 |
| `/interview` | 模拟面试 | 语音/文字对话、按 JD+简历出题、反馈报告 |
| `/tracker` | 求职看板 | Kanban：收藏→投递→沟通→面试→Offer→Passed |
| `/settings` | 设置 | LLM API、投递限额、浏览器 profile、黑名单 |

### 4.2 核心 UI 组件
- **简历编辑器**：分区块（基本信息/教育/经历/技能/项目）、拖拽排序、实时 A4 预览、模板切换（参考 Reactive-Resume）
- **匹配面板**：简历 vs JD 并排、关键词命中高亮、匹配分进度环、缺失技能清单
- **投递控制台**：待投列表（岗位卡片）+ 打招呼语（3 风格可选）+ 勾选 → 「确认投递」按钮 → 实时进度流
- **模拟面试**：聊天气泡、语音（可选）、出题区、评分报告（能力雷达图）
- **看板**：拖拽卡片、状态流转、统计图表

### 4.3 状态管理
Zustand store 分层：`resumeStore` / `jobStore` / `applyStore` / `trackerStore` / `settingsStore`，持久化到 SQLite（经后端 API）。

### 4.4 设计原则
- 中文界面、操作路径 ≤3 步
- 所有 AI 生成内容**可预览、可编辑、可撤回**
- 投递类操作**双确认**（勾选 + 确认按钮）

## 5. 后端设计（Python + FastAPI）

### 5.1 模块划分
```
backend/
├── main.py                 # FastAPI 入口，CORS(localhost)，启动时初始化 DB
├── config.py               # 配置加载（API key、限额、路径）
├── db.py                   # SQLAlchemy engine/session（SQLite）
├── models.py               # ORM 模型
├── routers/
│   ├── resume.py           # 简历解析/优化
│   ├── jobs.py             # 岗位 CRUD/抓取触发
│   ├── match.py            # 匹配打分
│   ├── apply.py            # 投递（prepare/confirm）
│   ├── interview.py        # 模拟面试会话
│   └── tracker.py          # 看板/统计
├── services/
│   ├── resume_parser.py    # PDF/DOCX→结构化（pdfplumber/pypdf/python-docx）
│   ├── matcher.py          # FastEmbed 向量 + 关键词 + LLM 打分
│   ├── optimizer.py        # LLM 简历优化（STAR/ATS/中文）
│   ├── greeting.py         # LLM 打招呼语（多风格）
│   ├── interviewer.py      # 模拟面试（LLM+RAG）
│   ├── apply_ctrl.py       # 投递状态机/限速/去重
│   └── boss_browser.py     # DrissionPage BOSS 封装
├── llm.py                  # 统一 LLM 客户端（DeepSeek/Qwen 切换）
└── schemas.py              # Pydantic 请求/响应模型
```

### 5.2 后端进程与并发
- Uvicorn 单进程本地运行；异步接口（async/await）
- 浏览器自动化（DrissionPage）在**独立线程/子进程**中运行，避免阻塞 API
- 长任务（抓取/投递/模拟面试）用 WebSocket 推送进度

### 5.3 配置（settings.json，本地）
```json
{
  "llm": { "provider": "deepseek", "api_key": "", "model": "deepseek-chat", "base_url": "" },
  "apply": { "daily_limit": 15, "interval_seconds": [45, 120], "halt_on_risk": true },
  "browser": { "user_data_dir": "", "headless": false },
  "blacklist": { "companies": [], "keywords": ["外包","猎头","培训"] },
  "cities": ["广州", "深圳", "远程"]
}
```

## 6. 浏览器执行层设计（BOSS 直聘适配）

### 6.1 DrissionPage 封装（`boss_browser.py`）
| 操作 | 说明 |
|------|------|
| 登录 | 打开真实 Chrome，用户扫码/账号登录，cookie 持久化到 user-data-dir |
| 搜索岗位 | 关键词+城市 → 列表页翻页采集 → 结构化入库（去重） |
| 读取岗位详情 | 职责/要求/薪资/公司/HR 活跃度 |
| 打招呼 | 向 HR 发送开场白（可选图片简历） |
| 读取聊天 | 获取 HR 回复（供 AI 回复/状态更新） |

### 6.2 风控策略（核心）
- **非 headless**（可见浏览器）
- **每日上限 15**，随机间隔 45–120 秒
- **人工接管**：验证码/滑块/异常 → 立即暂停并通知用户
- **风控熔断**：检测到降权/封号迹象 → 停止所有自动操作
- **黑名单**：外包/猎头/培训等关键词过滤；公司去重

### 6.3 失败处理
- 投递失败重试 ≤3 次，失败记录原因（参考 hunter-delivery 熔断）
- 全部操作写日志（SQLite `apply_log`）

## 8. API 接口设计（前后端本地 HTTP）

### 8.1 REST
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/resume/parse` | 上传简历文件 → 结构化 JSON |
| PUT | `/api/resume` | 保存简历结构 |
| POST | `/api/resume/optimize` | 优化简历（body: {target_job?, style}）→ 生成稿 |
| GET | `/api/resume/templates` | 模板列表 |
| GET/POST | `/api/jobs` | 岗位列表/录入 |
| POST | `/api/jobs/scan` | 触发 BOSS 抓取（body: {keyword,city,pages}） |
| GET | `/api/jobs/{id}/match` | 简历↔该岗位匹配报告 |
| POST | `/api/match/batch` | 批量匹配（岗位库） |
| POST | `/api/apply/prepare` | 为选定岗位生成打招呼语（→ 待确认队列） |
| POST | `/api/apply/confirm` | **人类确认**后投递（body: {job_ids, greeting}） |
| GET | `/api/apply/pending` | 待确认投递列表 |
| POST | `/api/interview/start` | 开始模拟面试（body: {job_id?}） |
| POST | `/api/interview/answer` | 提交回答 → 追问/反馈 |
| GET | `/api/tracker` | 看板数据（按状态分组） |
| PUT | `/api/tracker/{id}/status` | 更新岗位状态 |
| GET | `/api/settings` / PUT | 配置读写 |

### 8.2 WebSocket
| 通道 | 用途 |
|------|------|
| `/ws/scan` | 岗位抓取实时进度 |
| `/ws/apply` | 投递执行实时进度 |
| `/ws/interview` | 模拟面试流式对话 |
| `/ws/risk` | 风控事件通知（需人工接管） |

### 8.3 数据格式（Pydantic schemas）
统一 `{code: 0, data: {...}, message: ""}` 响应格式；所有 AI 生成带 `source:"ai"|"edited"` 标记。

## 10. AI 集成设计

### 10.1 LLM 客户端（统一）
- 适配 DeepSeek/Qwen/OpenAI 兼容接口（`base_url` + `api_key`）
- 流式输出（SSE/WebSocket）支持
- Token 用量统计 + 缓存（同岗位 24h 内不重复调用，lakejobai 思路）

### 10.2 匹配引擎（Resume-Matcher 思路）
1. **向量相似度**：FastEmbed 对简历+JD 编码 → cosine 相似度
2. **关键词匹配**：JD 提取技能词 vs 简历命中 → 命中率/缺口
3. **LLM 综合打分**：0-100，规则：技能命中 + 目标岗位 + 排除词归零
4. 输出：分项得分、缺失技能清单、优化建议

### 10.3 提示词工程（中文）
- 简历优化：STAR 法改写经历、ATS 关键词注入、毒舌点评（可选）
- 打招呼语：3 风格（专业/热情/简约）+ 岗位相关性
- 模拟面试：按 JD+简历出题（行为面/专业面/简历面），追问，最终评分报告

## 14. 风险与备选

| 风险 | 概率 | 应对 |
|------|------|------|
| BOSS 改版反爬 | 高 | 执行层隔离，随时可停投递；DrissionPage 选择器集中维护 |

### 📊 总体评估（评审结论）
架构方向正确（决策/执行解耦 + 人类把关 + 本地隐私 + P0-P3 零风险先行 + 模块化 roadmap），**具备实施骨架**。但**不能直接全量实施**：
1. 先完成 **P0-P3**（简历/匹配/优化/打招呼，纯工具零风险）
2. 用**打包 spike** 验证分发链路
3. 进入 **P4-P5**（抓取/投递）前，必须补齐：本地鉴权、API key 加密、投递幂等、浏览器队列互斥、选择器回归机制——否则封号与安全风险随投递模块一并上线。
